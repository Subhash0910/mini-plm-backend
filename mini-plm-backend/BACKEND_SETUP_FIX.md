# Backend Build Fix Guide - January 16, 2026

## 🔧 Issue: Maven Compilation Errors

### Error Messages
```
[ERROR] cannot find symbol: method getBomLines()
[ERROR] cannot find symbol: method getId()
[ERROR] cannot find symbol: method getPartNumber()
```

### Root Cause
Lombok annotation processor not generating getter/setter methods due to:
1. Maven cache containing old compiled classes
2. Stale `.class` files in `target/` directory  
3. Annotation processing not running on rebuild

---

## ✅ SOLUTION: Clean Maven Build

### Step 1: Navigate to Backend Directory
```bash
cd C:\mini-plm\mini-plm-backend\mini-plm-backend
```

### Step 2: Clean Maven Cache
```bash
# Remove all compiled files and cache
mvn clean
```

### Step 3: Remove IDE Cache (if using IntelliJ/Eclipse)
```bash
# IntelliJ IDEA
rmdir /s .idea
# OR delete the .idea folder manually

# Eclipse
rmdir /s .classpath .project .settings
```

### Step 4: Fresh Compilation
```bash
# Download dependencies and compile with annotation processing
mvn clean compile
```

### Step 5: Full Build
```bash
# Full build without running tests
mvn clean install -DskipTests

# OR full build with tests (slower)
mvn clean install
```

### Step 6: Start Application
```bash
# Start Spring Boot application
mvn spring-boot:run

# Application will be available at: http://localhost:8080
```

## ⚠️ Troubleshooting

### If errors persist after `mvn clean`:

1. **Check Java version:**
   ```bash
   java -version
   # Should be JDK 17+
   ```

2. **Remove entire target directory:**
   ```bash
   rmdir /s /q target
   mvn clean
   ```

3. **Force update dependencies:**
   ```bash
   mvn clean install -U -DskipTests
   ```

4. **Rebuild IDE cache:**
   - IntelliJ: File → Invalidate Caches → Invalidate and Restart
   - Eclipse: Project → Clean All
   - VS Code: Run `mvn clean` then reload
